# ACTIVSg2000 scenario package

The production game uses the public synthetic Texas ACTIVSg2000 model. The
canonical classroom release is the representative-day package
`data/processed/activsg2000_representative_v1`: 5 representative days x 24
one-hour periods = 120 periods that together stand for the next ten years of
the game. There are no calendar years in the game; the source year labels
below (2027--2029) belong to the derivation input only. They are not historical source-data years or forecasts.

## Representative-day package

The package is built from the 2028 blocks of the hourly source package
(below) by:

    PYTHONPATH=src:. python3 -m tools.activsg2000.build_representative_package

(`--source-package`, `--output-dir`, `--source-year` and `--skip-validation` override
the defaults). The 366 days of 2028 are described by their 24-hour system load
divided by the annual peak hour, clustered into four groups with deterministic
PAM k-medoids (no random numbers), and each medoid becomes a representative
day. The day with the annual peak hour is added as a fifth day with weight
exactly 1. The other weights are cluster sizes scaled so that all five weights
sum to 365:

| Day | Date | Source block | Weight | Periods |
|---:|---|---|---:|---|
| 0 | 2028-01-03 | `jan_jun` | 83.77 | 0-23 |
| 1 | 2028-05-10 | `jan_jun` | 99.73 | 24-47 |
| 2 | 2028-07-12 | `jul_dec` | 82.77 | 48-71 |
| 3 | 2028-09-10 | `jul_dec` | 97.73 | 72-95 |
| 4 | 2028-09-15 (peak day) | `jul_dec` | 1 | 96-119 |

The system peak is period 109. `representative_days.csv` and `manifest.json`
record the selection, the weights, and the source periods. Bus demand is
materialized in `demand_bus.csv` (one row per period); generators, branches
and DC lines are copied from the source block with static limits. The
manifest reports `validation_status: passed` only after every one of the 120
periods solves the single-period DCOPF, and the output is byte-identical
across reruns.

The scoring rules `data/teaching/dispatch_scoring_rules_representative_v1.json`
(from `scripts/create_representative_scoring_rules.py`) weight period `t` by
`1 h x day weight x 7.0236` (ten-year annuity factor at 7%); the weights sum
to 61,526.57 hours.

## Hourly source package

This section describes the hourly source package
(`data/processed/activsg2000_scenarios_v1`), which is built locally and is not
published in this repository. It is only the input of the representative-day
builder; students and the evaluator never need it.

The package is generated by:

    PYTHONPATH=src python tools/activsg2000/build_scenario_package.py \
      --source-dir path/to/ACTIVSg2000 \
      --output-dir data/processed/activsg2000_scenarios_v1

It contains:

    data/processed/activsg2000_scenarios_v1/
      manifest.json
      profile_parameters.json
      network/
      2027/jan_jun/
      2027/jul_dec/
      2028/jan_jun/
      2028/jul_dec/
      2029/jan_jun/
      2029/jul_dec/

The source topology is fixed at 2,000 buses, 3,206 branches, and 544
generators. Each block exposes the catalog files required by the CSV checker.
Hourly demand is generated deterministically from the profile recipe, so the
repository does not need to store hundreds of millions of repeated CSV cells.
The active release uses the dataset's static generator status, PMIN, and PMAX
limits. ACTIVSg2000 does not provide generator technology labels or hourly
availability data, so no synthetic wind/solar derating is applied.

### Scenario construction

Bus demand starts from the ACTIVSg2000 bus PD values and uses a bounded
calendar-aware seasonal, daily, and weekly multiplier. Active generators use
their catalog status, PMIN, and PMAX values in every hour. Generator marginal
costs and branch limits are copied from the public ACTIVSg2000 files.

This is a controlled instructional scenario package. 2028 is the leap-year
calendar block; 2027 and 2029 are non-leap-year blocks. It is not historical
ERCOT telemetry, an official ERCOT model, or a forecast.

### Hourly validation

Full six-block DCOPF validation is pending in this environment: the optional
`highspy` dependency is unavailable, so the checked-in root and block manifests
are explicitly `validation_status: unverified_dependency`. This is not a
successful validation claim, and the evaluator fails closed until a complete
HiGHS-backed run succeeds.

Before a block can be used, install `highspy` and run:

    PYTHONPATH=/path/to/highspy:.:src python3 \
      tools/activsg2000/validate_scenario_package.py \
      --package data/processed/activsg2000_scenarios_v1

The validator materializes all 26,304 hourly states, solves a DCOPF for each
state, records failed periods, and changes the root and block manifests to
`validation_status: passed` only if every state is feasible. A missing-`highspy`
runtime error remains `unverified_dependency` rather than becoming a generic
solver failure. The evaluator fails closed when a block manifest is missing or
not passed.

A partial smoke run can be requested with --max-hours, but it never produces
a usable production manifest.

The source blocks are 4,344 hours for January--June in non-leap years (2027
and 2029), 4,368 hours for January--June in the leap year 2028, and 4,416
hours for July--December.
